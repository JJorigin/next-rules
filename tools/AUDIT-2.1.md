## 接入与维护改进

- YouTube 独立分组，默认跟随 Google，可单独选择线路。登录域名继续按自身分类处理。
- 51 项平台条目分为全球、亚太流媒体。地区专用服务先于总分类，Apple TV+ 先于通用 Apple；共享 CDN 和门户域名保留边界。TikTok 不增加专用规则。
- HTTP 提供者使用明确的代理出口下载；代理组和缓存名称冲突时仅改新对象，原订阅依赖保留。脚本重复应用不累加新组。
- 自动生成备用规则，覆盖首次 HTTP 下载失败；Telegram 仍使用维护中的 MRS，并保留客户端 GeoIP 补充。
- 定时同步完整来源、生成视图和备用内容，验证失败不提交。测试和维护方法见 [MAINTAINING.md](MAINTAINING.md)。

## 验收结果与边界

3X-UI v3.11.0 的合并函数与官方源码一致；重新编译的适配器通过两种 DNS 选项的合并检查。实际 YAML 经过解析后，与 JS 生成的规则图相同。

Mihomo 1.19.33、1.19.34 各通过 577 项断言；FlClash Windows 0.9.3 发行内核通过 501 项。两套 Mihomo 各通过 16 项 HTTP 下载和缓存更新断言，合计 1,687 项。另有策略、生成一致性、来源完整性和同步器异常输入检查。

测试覆盖候选节点、空组、两种入口、国内目标与进程、已知 IP 加嗅探、IPv6 目标、服务分类、YouTube 跟随及独立选择、UDP 保护、首次下载失败，以及缓存更新成功和失败。DNS、TUN、IPv6、hosts 等原始客户端字段保留。

所有测试节点和观察出口均在本机回环，不使用用户订阅、真实节点或用户 IP。使用了当次官方分类数据库，摘要见机器记录。

这些结果证明已列输入下的规则和内核行为。实际设备的 TUN 接管、严格路由、DNS、公网出口，以及具体服务的登录、播放和通话，需要在装机环境验收。保留用户手选 DIRECT；分流不会被描述为全面 WebRTC 防泄露。上游格式正确但语义不完整的远程更新，也不能仅凭内核的格式解析保证安全，需要持续监测维护任务。
