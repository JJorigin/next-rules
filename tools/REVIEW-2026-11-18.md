## 确认的问题与处理

| 问题 | 复现或依据 | 本地处理 |
| --- | --- | --- |
| 主配置仍嵌入大量域名和 IP | 生成器把维护数据中的 payload 一起展开到 HTTP 提供者，因而 YAML 和 JS 同时包含远程 URL 和内置副本 | 从生成环节排除 HTTP payload；仍保留远程 URL、更新周期、代理下载及缓存路径。维护样本和独立远程规则文件继续保留 |
| 域名晚解析导致专用网段漏匹配 | 同一个模拟地址，以已有 IP 访问能进入 AI、Telegram 或 Netflix 对应组；以未归类域名访问时，专用网段的 no-resolve 条件先跳过，稍后解析出地址也不会重跑前面的规则，最后进入默认代理 | 明确服务域名先匹配；对未归类域名解析后，依次判断局域网、专用网段、普通国内地址，再执行进程兜底 |
| 域名解析到局域网也可能进入默认代理 | 早期 private IP 规则不解析，后面只判断国内地址，解析出的私有地址错过了前面的 private 条件 | 同一修正增加晚解析后的 private 地址判断 |
| FlClash 操作说明遗漏 | v0.9.3 官方模型默认将查找进程设为 off，而简化 README 时删去了启用提示 | 补回开启“查找进程”的说明；继续保留用户原客户端设置 |
| 分类数据库更新没有独立定时验证 | 原同步工作流仅在来源数据发生变化时执行真实内核测试，数据库单独变化时可能不触发 | 增加每日完整验证；实际调度以 GitHub Actions 为准 |

还将维护下载器的认证跳转保护扩展到协议和端口变化。工作流令牌只用于 GitHub API，跨来源或降级跳转移除认证头，并补充离线检查。

本地候选的三套常规回归各通过 569 项断言，域名解析路径共通过 216 项断言，两套 HTTP 缓存测试各通过 16 项断言，合计 1,955 项。另有 5 项离线来源校验测试通过。计数只表示本次测试范围内的结果，不代表覆盖了所有使用情形。

测试仅使用本机模拟节点和出口，不读取用户订阅或真实节点。私有地址及服务商地址均为模拟目的地址，不会实际连接。测试输入及结果摘要见本目录同名 JSON 记录。

## 必须明确的边界

移除内置副本后，首次 HTTP 下载失败且没有有效缓存时，提供者会为空。Mihomo 仍可能匹配后续规则，不会因此自动阻断全部流量。这项限制不能靠只删 payload 消除。首次接入和批量部署前必须确认所需规则集加载成功；已有有效缓存时，下载失败可继续使用缓存。

格式正确但内容不完整的远程文件，仍可能被内核接受。本项目的源同步校验能拦截已知异常，但不能给客户端直接读取的所有上游更新提供逐次发布担保。多个远程来源也各有更新与缓存周期，不能承诺同时刷新。

完整 AI 来源本身包含共享基础设施条件，来源的分类范围不等同于“只属于 AI 的独占服务”。本次未人工删选原始主清单。规则测试也不等于实际服务登录、播放、地区解锁或全面 WebRTC 防护。
